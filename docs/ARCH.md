# AFDX 端系统设计说明

本文说明当前端系统的输入、输出、模块分工和设计依据，供编写设计文档时引用。表规格、字段、地址和时间参数均为当前 RTL 的设计值；资源、时序、吞吐、时延、抖动及 RTC 误差的实测结果见[事实清单](FACTS.md)，逐项回归见[补充数据](FACTS_DETAIL.md#逐项回归与评委入口)。

## 1. 总体设计

### 1.1 目标与设计依据

航空电子全双工交换式以太网（Avionics Full-Duplex Switched Ethernet，AFDX）端系统把应用消息经两路以太网发送，并将收到的有效消息交给应用。虚拟链路（Virtual Link，VL）是一组独立的通信配置：发送端用它选择地址、端口和最小发送间隔，接收端用虚拟链路标识（Virtual Link Identifier，VLID）找到接收配置。

本设计提供用户发送、用户接收、网络管理、数据加载和卸载、时钟同步。发送支持 128 条 VL 配置，接收支持 4096 条 VL 配置；这两个数表示配置规模，缓存容量见第 9 节。

赛题依据为《中科亿海微.pdf》选题一正文第 2–4 页；答疑依据为《FPGA创新大赛问题汇总1010.xlsx》Sheet1，以下 R 表示工作表行号。

| 依据 | 对本设计的影响 |
|---|---|
| 赛题选题一 | 实现 ARINC 664 Part 7 通信、高完整性通信、SNMP、615A 和 RTC；顶层采用官方八端口模板 |
| 答疑 R3、R59、R61 | 采用八位千兆媒体独立接口（Gigabit Media Independent Interface，GMII），时钟为 125 MHz，与每拍一字节的接口匹配 |
| 答疑 R46、R57 | MAC 核可调用 eLinx IP；评测使用参赛者的测试平台，综合后仿真即可，厂商 IP 可用生成的网表仿真 |
| 答疑 R49、R50、R62 | 可增加接口；GMII 的 `valid` 表示当拍字节有效，`ready` 不参与线路握手；本设计增加 B 网、应用和配置接口 |
| 答疑 R58、R60 | 吞吐须达到 100 Mbps，GMII 接口时延不超过 2 ms；测量起止点与工况在事实清单中说明 |
| 答疑 R30 | 器件可自行选择；工程选用 EQ6HL130 / CSG484_H，这是工程选择 |
| 答疑 R12、R47、R48 | 协议版本未被指定，功能应参考协议规范；当前版本依据见事实清单“协议版本依据”，支持范围见第 6、9 节 |

媒体访问控制（Media Access Control，MAC）采用本工程的 `afdx_mac_tx` 和 `afdx_mac_rx`，负责前导码、帧边界、校验和帧间隔。单时钟和自研 MAC 是本设计的实现选择。工程交付以 eLinx 与 ModelSim 的编译、仿真和报告为入口。

### 1.2 整体结构

~~~text
应用消息 ─┐
RTC ──────┤
SNMP ─────┼─► afdx_svc ─► afdx_tx_core ─► A / B 网 GMII
615A ─────┘                  │
                         分页缓存、VL 调度、组帧、双网 MAC

A / B 网 GMII ─► afdx_rx_core ─► afdx_svc ─► 应用 / 三项服务
                 │
             双网 MAC、协议检查、VL 查表、序号检查、冗余去重、交付

配置口 ─► afdx_cfg ─► 收发配置表、统计寄存器、服务寄存器
时钟与复位 ─► afdx_timebase 和各模块
~~~

逐 VL 的配置和状态放在块随机存取存储器（Random Access Memory，RAM）中，由状态机顺序访问，控制逻辑不随 VL 数量展开成大量并行比较器。帧内字节通路用预读和寄存流水维持每拍一字节；发送调度提前选择即将到期的 VL，为下一帧准备元数据。

### 1.3 顶层端口与消息接口

顶层名为 `AFDX_top`。官方八个端口的名称、方向和位宽如下。

| 端口 | 方向 | 含义 |
|---|---|---|
| `clk` | 入 | 125 MHz，周期 8 ns，全设计在上升沿工作 |
| `reset` | 入 | 同步复位，高有效，是当前 RTL 的复位定义 |
| `tx_data[7:0]`、`tx_valid` | 出 | A 网 GMII 发送字节及有效指示，包含前导码和帧校验序列 |
| `rx_data[7:0]`、`rx_valid` | 入 | A 网 GMII 接收字节及有效指示 |
| `tx_ready` | 出 | 两个收发核心均初始化完成后为 1 |
| `rx_ready` | 入 | 不参与线路传输 |

扩展端口用于双网、应用消息、配置和观察。

| 端口 | 方向 | 含义 |
|---|---|---|
| `tx_data_b[7:0]`、`tx_valid_b` | 出 | B 网 GMII 发送 |
| `rx_data_b[7:0]`、`rx_valid_b` | 入 | B 网 GMII 接收 |
| `app_tx_valid`、`app_tx_data[7:0]`、`app_tx_last`、`app_tx_vl[6:0]` | 入 | 应用发送字节、消息末字节标记、发送 VL 索引 |
| `app_tx_ready` | 出 | 服务仲裁器选中应用且发送核心 `m_ready` 为 1 时允许传输 |
| `app_tx_port_en`、`app_tx_sport[15:0]`、`app_tx_dport[15:0]` | 入 | 为 1 时使用消息自带的 UDP 源、目的端口，否则使用 VL 默认端口 |
| `app_rx_valid`、`app_rx_data[7:0]`、`app_rx_last`、`app_rx_vl[11:0]`、`app_rx_port[15:0]` | 出 | 未被服务认领的交付消息；给出字节、末字节、接收配置索引和目的端口 |
| `app_rx_sport[15:0]`、`app_rx_net` | 出 | 交付消息的源端口和来源网，0 为 A，1 为 B |
| `cfg_wr`、`cfg_rd`、`cfg_addr[17:0]`、`cfg_wdata[31:0]` | 入 | 按 32 位字寻址的配置读写请求 |
| `cfg_rdata[31:0]`、`cfg_rvalid`、`cfg_ready` | 出 | 配置读回和写就绪 |
| `ev_tx[6:0]` | 出 | 发送接纳、四种拒收和两网发送完成事件，位定义见第 5 节 |
| `ev_a[7:0]`、`ev_b[7:0]`、`ev_rm_drop`、`ev_deliver` | 出 | 两网接收分类、冗余丢弃和接纳交付事件 |
| `ev_gdrop[1:0]` | 出 | 预留事件口，取值及对应计数见第 5 节 |

应用发送只有 `valid` 与 `ready` 同拍为 1 才传输一个字节。消息首字节握手时锁存 `vl`、`port_en`、`sport`、`dport`，`last` 标记末字节；等待期间发送方保持待传字节和 `last`。应用接收没有反压接口，`valid` 为 1 时必须接收，`last` 与末字节同拍。

GMII 只用 `valid` 定义字节有效。`tx_valid` 从第一个前导字节到最后一个帧校验字节连续为 1；`rx_valid` 上升开始一段输入，下降结束。A、B GMII 直接连接收发核心，帧内每拍一字节。模块参数默认值为 `TX_PAGE_AW`=8、`TX_OFF_AW`=9、`LOOKAHEAD`=512、`RX_RING_AW`=12、`RX_DQ_AW`=5。

## 2. 帧格式与时间基准

### 2.1 以太网、IPv4 和 UDP 帧

用户数据报协议（User Datagram Protocol，UDP）承载应用或服务消息。令 `n` 为消息字节数，1 ≤ `n` ≤ 1471。下表字节位置从目的 MAC 地址第一个字节起算，报文字节常量用十六进制表示，多字节字段按高字节先发。

| 字节位置 | 长度 | 内容 |
|---|---|---|
| 0–3 | 4 | 目的 MAC 固定部分：03 00 00 00 |
| 4–5 | 2 | VLID |
| 6–8 | 3 | 源 MAC 固定部分：02 00 00 |
| 9–10 | 2 | `USER_ID`，端系统用户编号 |
| 11 | 1 | 网络接口号：A 为 `0x20`，B 为 `0x40` |
| 12–13 | 2 | 08 00，表示网际协议（Internet Protocol，IP）的 IPv4 报文 |
| 14–33 | 20 | IPv4 头：45 00、总长度 `n`+28、16 位标识、00 00、TTL 01、协议 11、头校验和、源 IP、目的 IP |
| 34–41 | 8 | UDP 头：源端口、目的端口、长度 `n`+8、校验和 0000 |
| 42 起 | `n` | 消息数据 |
| 数据之后 | max(17−`n`, 0) | 短消息补零，使数据与填充合计至少 17 字节 |
| 填充之后 | 1 | 序列号（Sequence Number，SN） |
| 最后 | 4 | 帧校验序列（Frame Check Sequence，FCS），由 MAC 生成 |

含 FCS 的帧长为 47+max(`n`,17)，范围 64–1518 字节。线上在帧前增加七个 55 和一个 D5，帧后空闲至少 12 拍。A、B 冗余副本只有源 MAC 的接口号和 FCS 不同。

每条 VL 复位后的首帧 SN 为 0，后续为 1、2、…、255、1、2、…。IPv4 标识是发送组帧器的全局 16 位计数，首帧从 0 开始，每授权一帧加 1。目的 IP 直接取发送配置；组播配置使用 224.224.VLID[15:8].VLID[7:0]，即 `0xE0E00000` | VLID，615A 对接使用对端单播 IP。

循环冗余校验（Cyclic Redundancy Check，CRC）的 CRC32 使用反射多项式 `0xEDB88320`，初值全 1，结果取反、低字节先发，范围从目的 MAC 到 SN。组合模块 `afdx_crc32_d8` 每次处理一个字节，收发共用相同算法。

### 2.2 调度和冗余时间

| 信号 | 定义与用途 |
|---|---|
| `now[31:0]` | 复位为 0，每拍加 1，约 34.36 秒回绕；发送调度比较时间差的符号位 |
| `byte_en` | 复位为 0，正常工作每拍为 1，允许 MAC 推进一个字节 |
| `now_c[15:0]` | `now[27:12]`，每 4096 拍增加 1，单位 32.768 µs，约 2.147 秒回绕；用于接收冗余窗口和老化 |

上述信号由 `afdx_timebase` 产生。带宽分配间隔（Bandwidth Allocation Gap，BAG）以完整时钟周期表示，1 ms 对应 125000 拍，允许非 8 的整数倍。由于发送时间比较采用 32 位相减看符号位，配置约定 BAG 不超过 2^30 拍，留出回绕比较的余量；RTL 不对该上限做自动限幅。

## 3. 发送侧设计

### 3.1 分页缓存与表分工

~~~text
消息 ─► afdx_tx_buf ─► tx_payload / tx_pnext
              │ 入队                │ 预读
              ▼                     ▼
        afdx_tx_engine ─授权─► afdx_tx_builder ─► afdx_mac_tx ─► A / B
        tx_cfg / tx_state      帧头、载荷、填充、SN
~~~

`afdx_tx_core` 实例化发送表并连接各模块。表使用 `afdx_ram_sdp`：一个写口、一个同步读口，各端口有明确的控制者。

| 表 | 默认深度×位宽 | 写口控制者 | 读口控制者 | 内容 |
|---|---|---|---|---|
| `tx_cfg` | 1024×32 | 配置口，初始化时为清表逻辑 | `tx_engine` | 每条 VL 占 8 字地址槽 |
| `tx_state` | 128×63 | `tx_engine` | `tx_engine` | `timer_active[62]`、`next_time[61:30]`、`sn[29:22]`、`q_count[21:16]`、`q_head[15:8]`、`q_tail[7:0]` |
| `tx_mnext` | 256×8 | `tx_engine` | `tx_engine` | 同一 VL 的下一条消息首页号 |
| `tx_desc` | 256×44 | `tx_buf` | `tx_engine` | len[43:33]、`port_en[32]`、`sport[31:16]`、`dport[15:0]`，以首页号寻址 |
| `tx_pnext` | 256×8 | `tx_buf` | `tx_builder` | 同一消息的下一页号 |
| `tx_payload` | 131072×8 | `tx_buf` | `tx_builder` | 地址为页号[7:0]与页内偏移[8:0]拼接，合计 128 KiB |
| `tx_free` | 256×8 | `afdx_tx_free` | `afdx_tx_free` | 空闲页号先进先出队列（First-In First-Out，FIFO） |

`tx_cfg` 的地址为 {`vl[6:0]`,`w[2:0]`}，每条 VL 的字段如下。

| 字序号 `w` | 字段 |
|---|---|
| 0 | `en[0]`、`net_a[1]`、`net_b[2]`、qmax[8:3]、`max_payload[19:9]` |
| 1 | `bag[31:0]`，单位时钟周期 |
| 2 | vlid[15:0] |
| 3 | 源 IP[31:0] |
| 4 | 目的 IP[31:0] |
| 5 | 默认源端口[31:16]、默认目的端口[15:0] |
| 6、7 | 保留 |

qmax 是本 VL 的排队条数上限，`max_payload` 是允许的消息长度。`en` 为 0 或 `net_a`、`net_b` 都为 0 时拒收。每个地址槽有 8 个字，其中 6 个字定义有效内容；配置应在该 VL 没有排队或在途消息时完成。

页池为 256 页，每页 512 字节，最长消息占 3 页。`afdx_tx_free` 初始化时顺序装入全部页号；取页口供 `tx_buf` 使用，还页口分别供 `tx_builder` 和 `tx_buf` 使用，同时归还时 `tx_builder` 优先。按页分配可以让短消息只占需要的页，消息描述与首页共用索引。

### 3.2 接收消息与拒收

发送核心的消息口为 `m_valid`、`m_ready`、`m_data[7:0]`、`m_last`、`m_vl[6:0]`、`m_port_en`、`m_sport[15:0]`、`m_dport[15:0]`，握手和首字节元数据定义同应用口。

1. 首字节握手后，`tx_buf` 暂存该字节并申请首页。申请期间 `m_ready` 为 0，页申请返回后将首字节写入缓存。
2. 后续字节每拍写入 `tx_payload`；跨页时暂停输入，申请新页，并在 `tx_pnext` 中登记页链。六个页号寄存器记录本条消息已占页，供失败回收使用。
3. 末字节写入后保存 `tx_desc`，向 `tx_engine` 请求入队；等待回答时不接收下一条消息。
4. `tx_engine` 依次检查 VL/网络使能、`max_payload`、qmax，成功则登记到本 VL 队尾，失败返回对应原因。
5. 超过 1471 字节、页申请失败或入队被拒绝时，归还本条消息全部已占页。若尚未收到 `last`，则继续握手消费剩余字节并丢弃，到 `last` 后报告一次结果。无页不会无限等待，也不会把残余字节当成下一条消息。

每条消息产生一次 accept 或 drop_dis、drop_full、drop_long、drop_nopage 事件。拒收沿用第一次确定的原因，回收完成后才报告，避免下一条消息受未归还页影响。发送核心的检查预算为：入队回答不超过 64 拍，结果事件在消息末字节之后 96 拍以内，初始化后 `m_ready` 连续为 0 不超过 96 拍。这些预算针对核心消息口；应用口还受整消息服务仲裁影响。

### 3.3 VL 调度与 BAG

`afdx_tx_engine` 是 `tx_state` 的唯一写者。每条 VL 有独立队列和下一次允许发送时刻，跨 VL 轮询，同一 VL 内按入队顺序发送。

| 操作 | 触发与处理 | 操作预算 |
|---|---|---|
| 起始确认 | 收到实际起始时刻 `t_start`，写 `next_time`=`t_start`+`bag`，置 `timer_active`，释放该 VL 的待起始标记 | 16 拍内完成 |
| 入队 | 检查配置、更新队头/队尾与 `q_count`；符合提前窗口时可直接登记候选 | 开始处理后 16 拍内回答 |
| 授权 | 候选存在且下一帧槽可用，读取配置字 0–5、队首描述和下一消息指针，交出字段并出队，更新 SN | 24 拍内交出 |
| 扫描 | 无候选时按 VL 索引检查队列及到期时间 | 每 2 拍发起一条状态读取 |

扫描对 `now`−`next_time` 分拍相减，`timer_active` 为 0 或距离到期不超过 `LOOKAHEAD`=512 拍时可选为候选。空队列的 BAG 已到期时清 `timer_active`，避免长期空闲后回绕误判。流水中受状态写入影响的结果作废，从已完成扫描的位置继续。

入队与扫描用 16 条扫描配额协调，防止连续入队长期挡住轮询。扫描一轮和授权、帧头准备的预算放在提前窗口内。候选被授权后，该 VL 锁定到实际 `tx_sof`，避免在 `next_time` 尚未更新时再次授权。

`tx_builder` 可以同时容纳一帧字节流和一份下一帧元数据。提前准备的目的，是在 BAG 到期前算好帧头、校验和与页指针；线路可用且准备完成时按目标时刻起始。唯一候选槽被尚未到期的 VL 占用时，其他已到期小帧可能等待，因此任意混合小帧组合不保证线速。

### 3.4 组帧与双网 MAC

授权字段包括两网使能、VLID、源/目的 IP、源/目的端口、`n`、SN、首页号和允许起始时刻。消息 `port_en` 为 1 时覆盖默认端口。

`tx_builder` 顺序累加 IPv4 头校验和，准备预算不超过 32 拍。发送时将 42 字节协议头装入移位寄存器，随后依次输出载荷、短帧填充和 SN。时间判断提前 4 拍补偿计时与输出流水，实际起始以 MAC 的 `tx_sof` 为准，并由它更新 BAG 起点。线路空闲、没有其他帧且 BAG 已到时，核心从消息末字节到 `tx_sof` 的检查预算为 100 拍。

载荷读请求先寄存，经同步 RAM 和数据寄存流水进入 8 项字节 FIFO。帧头发送期间启动预读，当前页和下一页分开保存，跨页连续供数。页末数据已经进入 FIFO 且页链已取得后归还页；4 项归还 FIFO 与保持寄存器承接连续归还请求。

`afdx_mac_tx` 使用一个状态机、两套 CRC 和输出寄存器，两网同时发送；只在源 MAC 接口字节给出不同数据。其接口如下。

| 端口 | 方向 | 含义 |
|---|---|---|
| `clk`、`reset`、`byte_en` | 入 | 时钟、复位和字节推进允许 |
| `s_valid`、`s_ready` | 入/出 | 上游字节有效与 MAC 取字节握手 |
| `s_data_a[7:0]`、`s_data_b[7:0]` | 入 | 当前字节在两网上的值 |
| `s_last` | 入 | FCS 前最后一个字节，即 SN |
| `s_en_a`、`s_en_b` | 入 | 起始时采样的两网使能 |
| `tx_sof`、`tx_eof` | 出 | 第一前导字节起始、最后 FCS 字节结束后的事件 |
| `tx_underrun` | 出 | 数据阶段上游缺字节 |
| `tx_data_a[7:0]`、`tx_valid_a`、`tx_data_b[7:0]`、`tx_valid_b` | 出 | GMII 寄存输出 |

| 字节时段 | 线路行为 |
|---|---|
| 起始及前导 | 采样使能，发送 7 个 55；前导期间不取上游数据 |
| 第 8 个前导字节 | 发送 D5，同时取第一个帧字节 |
| 帧内容 | 每拍输出并取后续字节，取到 `s_last` 后停止取数 |
| FCS | 各网发送自己的 4 字节 CRC32 |
| 帧间隔 | `valid` 为 0，至少 12 拍；持续有帧等待时为 12 拍 |

未启用网的 `data`、`valid` 为 0，空闲 `data` 为 0。欠载时报告 `tx_underrun`，发送不取反的错误 CRC，消费本帧剩余字节到 `s_last` 后恢复；只有无欠载的 `tx_eof` 产生相应 `ev_tx_a`、`ev_tx_b`。短帧填充由 `tx_builder` 完成。复位后 MAC 先等待完整帧间隔才允许首帧。

发送核心还提供 `now`、`byte_en`、`user_id[15:0]` 输入，配置口 `cfg_we`、`cfg_addr[9:0]`、`cfg_wdata[31:0]` 与 `cfg_ok`，以及 init_done 和发送事件输出。`cfg_we` 与 `cfg_ok` 同拍为 1 才接受表写。

## 4. 接收侧设计

### 4.1 接收表与缓存

~~~text
A 网 ─► mac_rx ─► rx_parse ─► rx_ring_a ─┐
B 网 ─► mac_rx ─► rx_parse ─► rx_ring_b ─┤
                    │ 帧描述               ▼
                    └──► rx_engine ─► rx_deliver ─► 服务 / 应用
                         VL 映射、配置、状态
~~~

`afdx_rx_core` 实例化接收表，两网有各自的 MAC、解析器和载荷环，共用查表、序号检查、冗余管理及交付出口。

| 表或队列 | 默认规格 | 写口控制者 | 读口控制者 | 内容 |
|---|---|---|---|---|
| `rx_map` | 65536×13 | 配置口，初始化时为清表逻辑 | `rx_engine` | `valid[12]`、`idx[11:0]`，以 16 位 VLID 直接寻址 |
| `rx_cfg` | 4096×32 | 同上 | `rx_engine` | `en[0]`、`net_a[1]`、`net_b[2]`、ic_en[3]、`rm_en[4]`、`skew_max[16:5]`、`max_payload[27:17]` |
| `rx_state` | 4096×44 | `rx_engine` | `rx_engine` | 保留位[43]、`psn_a_valid[42]`、`psn_a[41:34]`、`psn_b_valid[33]`、`psn_b[32:25]`、`rm_time_valid[24]`、`rm_last[23:16]`、`rm_time[15:0]` |
| `rx_ring_a`、`rx_ring_b` | 各 4096×8 | 本网 `rx_parse` | `rx_deliver` | 未经提交与已提交的消息载荷 |
| `rx_dq` | 32 项寄存器，每项 `RX_RING_AW`+56 位 | `rx_engine` | `rx_deliver` | 来源网、环内起点、长度、`idx`、源/目的 UDP 端口 |

映射可以选择任意 4096 个 VLID；多个映射到同一 `idx` 的 VLID 共用接收配置和状态。`skew_max` 单位为粗时间刻度，即 32.768 µs。`RX_RING_AW` 控制每网环容量，`RX_DQ_AW` 默认 5，支持 1–5，交付队列由四组各 8 项选择，再寄存后选组。

每个环的读写指针都比地址多一位，可区分空和满，容量为完整的 2^`RX_RING_AW` 字节。解析器保存已提交写指针和试写指针；可用空间为容量减去已提交写指针与读指针的差。当前帧先试写，通过检查才提交，拒绝则回退。

### 4.2 MAC 与协议检查

`afdx_mac_rx` 先寄存 GMII 输入，每个有效周期处理一个字节。它识别任意个 55 后的 D5，包括直接以 D5 起始；其他前导内容或前导未结束即 `valid` 下降，判前导错误。四字节延迟流水保留末尾 FCS，后级只收到目的 MAC 到 SN 的内容。

| 端口 | 方向 | 含义 |
|---|---|---|
| `clk`、`reset`、`rx_data[7:0]`、`rx_valid` | 入 | 时钟、复位和 GMII 输入 |
| `m_valid`、`m_data[7:0]`、`m_first` | 出 | 去除前导和 FCS 的连续帧字节，首字节时 `m_first` 为 1 |
| f_end | 出 | 帧结束事件 |
| f_err[1:0] | 出 | 0 完好、1 FCS 错、2 帧长错、3 前导错，在 f_end 时有效 |
| f_len[10:0] | 出 | 含 FCS 的长度，超长时饱和为 1519 |

`valid` 下降时按前导、长度、FCS 顺序判定；长度须为 64–1518，CRC32 未取反累计值须为 `0xDEBB20E3`。最多向解析器输出 1514 字节，超长内容丢弃到 `valid` 下降。复位后先见低电平才允许新帧，输入两帧之间一个低周期即可分开。

`afdx_rx_parse` 边接收边按字节位置检查，不保存整个帧头。

- 目的 MAC 固定部分为 03 00 00 00，EtherType 为 0800，IPv4 首字节为 45，协议号为 11。
- IPv4 的 MF 位和分片偏移必须为 0，DF 位不限制；20 字节头校验和按 16 位回卷累加须为 FFFF。
- `n`=UDP 长度−8，须为 1–1471；IPv4 总长度为 `n`+28，含 FCS 帧长为 47+max(`n`,17)。
- UDP 校验和为 0 时不核对；非 0 时核对 IPv4 伪头、UDP 头和载荷，奇数载荷末尾按补一个零字节累加，结果须为 FFFF。以太网填充和 SN 不参与 UDP 校验。
- 短帧填充内容不影响接收判断；源 MAC、TTL 和目的 IP 等不在上述检查范围内。

解析器提取 VLID、UDP 两端口、`n`、SN，并在首载荷前完成容量判断。空间不足时不保存该帧载荷。结束时先采用 MAC 的错误类别，再判协议头错误、环溢出、完好；只有完好帧提交描述。描述含环内起点和 f_end 当拍的 `now_c`，在引擎接收前保持有效。UDP 校验折叠在结束流水完成后判定，避免遗漏最后载荷字节。

初始化完成前已经开始的输入帧整帧忽略，不计数、不提交描述；完成初始化不会将半帧认成新帧。

### 4.3 完整性检查、冗余管理与老化

`rx_engine` 空闲时处理有效帧描述；A、B 描述同时待处理时优先 A。它先查 `rx_map`，再查 `rx_cfg`、`rx_state`；映射无效、VL/本网未启用或载荷超过 `max_payload` 时拒绝。

完整性检查（Integrity Check，IC）由 ic_en 控制，每网维护独立的上一序号 PSN。首次接收、SN=0、SN 为 PSN 的下一个或下下个时通过；序号在 1–255 间循环，0 的下一个为 1。无论检查通过与否，都更新本网 PSN；ic_en 为 0 时不读改 PSN。

冗余管理（Redundancy Management，RM）由 `rm_en` 控制，两网共用最近交付的 SN 和到达时刻。时间差取 16 位有符号差的绝对值，规则如下。

| 条件 | 决定 |
|---|---|
| RM 关闭 | 通过前面检查的每份帧都可交付 |
| 没有有效 RM 时间记录，或到达间隔大于 `skew_max` | 作为新帧交付 |
| 窗口内 SN 等于 `rm_last` | 丢弃重复帧 |
| 窗口内 SN 或 `rm_last` 为 0，且两者不同 | 交付 |
| 窗口内 SN 在模 255 环上领先 `rm_last` 1–127 步 | 交付 |
| 其余 | 冗余管理丢弃 |

决定交付时，`rx_dq` 满则按溢出拒绝处理，环数据回退，RM 的最近交付记录不更新。成功时登记描述、提交环，并在 RM 启用时更新记录。IC 更新与 RM 交付记录分开，因此队满不把未交付帧登记为已交付。

`now_c` 改变时挂起一次老化检查，空闲时检查下一条 VL；距记录时刻超过 `0x4000` 粗刻度则清 `rm_time_valid`。帧处理优先，打断后同项重试，完成才推进索引。老化用于在粗时间半圈之前撤销旧记录，保证时间差判定的含义。

从取走描述到决定的检查预算为 64 拍，双网同拍结束时后处理份在帧尾后 150 拍以内。这是处理预算，不要求线路等待；两网近同时到达时不承诺按物理先后来选择交付来源。

### 4.4 连续交付

`rx_deliver` 从 `rx_dq` 队头取描述，对相应环进行预读，每拍输出一个字节。`n` 字节连续有效，`last` 与末字节同拍，VL、端口和来源网在消息期间保持不变。开始交付时描述槽即可释放，环空间随读指针前进释放。

| 接收核心端口 | 含义 |
|---|---|
| `now_c[15:0]`、`rx_data_a`/b[7:0]、`rx_valid_a`/b | 粗时间和两网输入 |
| `cfg_map_we`、`cfg_cfg_we`、`cfg_addr[15:0]`、`cfg_wdata[31:0]`、`cfg_ok` | 映射/配置写，写使能与 `cfg_ok` 同拍为 1 才接受 |
| `d_valid`、`d_data[7:0]`、`d_last`、`d_vl[11:0]` | 连续消息交付和接收配置索引 |
| `d_sport[15:0]`、`d_dport[15:0]`、`d_net` | 消息端口及来源网 |
| init_done、`ev_a[7:0]`、`ev_b[7:0]`、`ev_rm_drop`、`ev_deliver` | 初始化状态和处理事件 |

空闲时从帧尾到首个交付字节的检查预算为 200 拍，已有消息交付时下一条在前一末字节后 16 拍以内开始。出口只有每拍一字节：正常冗余双份去重后只交付一份，两路独立非冗余满速输入可能积压，按环或描述队列的容量处理。

## 5. 配置总线、复位和统计

### 5.1 字地址与配置写

配置地址按 32 位字编址，不是字节地址。没有全局收发使能，每条 VL 使用自己的 `en`。

| 字地址 | 读写与内容 |
|---|---|
| `0x00000` | RO，`VERSION`=`0xC3110000` |
| `0x00001` | RO，`STATUS` 位 0 为 `tx_ready`，其余为 0 |
| `0x00002` | RW，`USER_ID[15:0]`，复位 0 |
| `0x00040`–`0x00046` | RO，发送计数器，顺序见下表 |
| `0x00048`–`0x0004F` | RO，A 网接收计数器，顺序对应 `ev_a` |
| `0x00050`–`0x00057` | RO，B 网接收计数器，顺序对应 `ev_b` |
| `0x00058`、`0x00059` | RO，`rm_drop`、deliver |
| `0x0005A`、`0x0005B` | RO，a_gdrop、b_gdrop |
| `0x00080`–`0x00088` | RTC 寄存器，定义见第 6 节 |
| `0x00090`–`0x0009C`、`0x000A0`–`0x000A3` | SNMP 寄存器，定义见第 6 节 |
| `0x000B0`–`0x000BB` | 615A 寄存器，定义见第 6 节 |
| `0x01000`+`vl`×8+`w`，`vl`=0–127，`w`=0–7 | WO，`tx_cfg`，范围 `0x01000`–`0x013FF` |
| `0x10000`+VLID，VLID=0–65535 | WO，`rx_map`，写数据取位 12:0 |
| `0x20000`+`idx`，`idx`=0–4095 | WO，`rx_cfg` |

服务区中未定义的地址、表读和其他未映射地址读出 0，写未定义地址无效。TX 表译码为地址位 17:10 等于 00000100，映射表为位 17:16 等于 01，RX 配置为位 17:12 等于 100000。

写请求在 `cfg_wr` 与 `cfg_ready` 同拍为 1 时接受。普通寄存器当拍写；表写进入保持寄存器，下一拍起 `cfg_ready` 为 0，地址、数据和写使能保持到对应核心 `cfg_ok`。接受后下一拍恢复 `cfg_ready`，不受阻时低一拍，表写等待检查预算为 64 拍。

配置写避开引擎发起查表读取的周期。TX 的 `cfg_ok` 为 `enable` && `op`==IDLE && !`want_enq` && !`want_grant`；RX 为 `enable` && (`op`==IDLE || `op`==AGE) && !desc_a_valid && !desc_b_valid。外壳的写使能与引擎的读使能同沿寄存，下一拍作用于 RAM，避免依赖同地址读写结果。

多字配置没有事务原子性。应先排空该 VL，停用 `en`，写其余字段，再启用；不要在消息排队或在途时改变配置。

### 5.2 读取、复位与初始化

`cfg_rd` 在 t 拍有效，t+2 拍 `cfg_rvalid` 和 `cfg_rdata` 有效。读取不受 `cfg_ready` 限制，复位结束后可逐拍读；同拍读写同一寄存器读到旧值。计数读取包含 t−1 拍及以前的事件，不包含 t 拍新事件。

同步高有效复位清状态和计数，不依赖 RAM 的上电初值。发送核心清 `tx_cfg`、`tx_state` 并装入空闲页号；接收核心清 `rx_map`、`rx_cfg`、`rx_state`。`rx_map` 有 65536 次清零写入，还要等待最后写入和初始化收尾完成。两个 init_done 相与后打一拍形成 `tx_ready`，清表期间 `cfg_ready` 为 0。

应用应等待 `tx_ready` 再配置和发送；`app_tx_ready` 经服务仲裁器跟随发送核心，并不由两核心联合就绪门控。服务由 `tx_ready` 允许工作，接收核心按自身初始化状态屏蔽输入帧。复位打断的消息和半帧作废，发送输出归零，接收先等线路 `valid` 回低再识别新帧。

### 5.3 事件与计数

| 事件位 | 名称 | 含义 |
|---|---|---|
| `ev_tx[0]` | accept | 完整消息成功入队 |
| `ev_tx[1]` | drop_dis | VL 或两网发送未启用 |
| `ev_tx[2]` | drop_full | 本 VL 队列达到 qmax |
| `ev_tx[3]` | drop_long | 超过全局或 VL 载荷上限 |
| `ev_tx[4]` | drop_nopage | 首次或跨页申请无空闲页 |
| `ev_tx[5]`、`ev_tx[6]` | `tx_a`、`tx_b` | 本网正常发送完成 |
| `ev_a`/b[0] | good | MAC、协议头和载荷缓存检查通过 |
| `ev_a`/b[1] | fcs | FCS 错 |
| `ev_a`/b[2] | len | 帧长或前导错 |
| `ev_a`/b[3] | hdr | IPv4/UDP 头或校验和错 |
| `ev_a`/b[4] | unk | VLID 未映射 |
| `ev_a`/b[5] | cfg | 接收配置不允许 |
| `ev_a`/b[6] | ic | 完整性检查拒绝 |
| `ev_a`/b[7] | ovf | 载荷环或交付队列满 |
| `ev_rm_drop`、`ev_deliver` | `rm_drop`、deliver | 冗余管理丢弃、接纳进入交付队列 |

每网输入帧先有一次 MAC/解析类别事件；类别为 good 后，再有一次查表/序号/冗余/交付结果事件。good 不等于最终交付，`ev_deliver` 表示接纳入交付队列。所有计数为 32 位自然回绕，仅复位清零。预留 `ev_gdrop` 固定为 0，对应 `0x5A`、`0x5B` 计数也为 0。

## 6. 服务通道与三项服务

### 6.1 消息仲裁与接收认领

`afdx_svc` 让应用、RTC、SNMP、615A 共用发送核心。按应用、RTC、SNMP、615A 的顺序轮询待发来源，选中后保持到末字节握手；消息中停顿时保持所有权，完成后从下一来源开始。只有选中来源收到 `ready`，避免不同消息的字节混合。

三个服务发送口按 RTC、SNMP、615A 从低位到高位打包：`valid`/`ready`/`last`/`port_en` 各 3 位，`data` 为 24 位，`vl` 为 21 位，`sport`/`dport` 各 48 位。所有服务使用消息自带 UDP 端口。没有服务发送时，应用字节和 `ready` 组合通过，不增加缓存。

接收核心 d_* 广播到三个服务；服务依据目的 UDP 端口给出 claim，首字节的认领结果保存到 `last`。被任一服务认领的消息不向应用给 `valid`/`last`。服务不反压接收出口，配置时应保证服务端口互不冲突，收发 VL、地址和两网使能均通过普通配置表设置。

### 6.2 RTC：实时时钟和网络对时

实时时钟（Real-Time Clock，RTC）使用 32 位秒和 32 位纳秒，每拍增加 8 ns，纳秒达到 1000000000 时向秒进位。秒起点为 2000-01-01 00:00:00 UTC；网络时间协议（Network Time Protocol，NTP）秒加 3155673600，接收时减回，按 32 位回绕。停用同步服务不停止时钟。

| 字地址 | 名称 | 读写与含义 |
|---|---|---|
| `0x00080` | `CTRL` | RW，位 0 启用、位 1 主端；写位 2=1 装入暂存时间，位 2 读 0；复位 0 |
| `0x00081` | `PERIOD` | RW，从端请求间隔，单位拍，复位 125000 |
| `0x00082` | `TX_VL` | RW，低 7 位，复位 0，本端请求/回应使用的发送索引 |
| `0x00083` | `UDP_PORT` | RW，低 16 位，复位 123，作为发送源/目的端口和接收认领端口 |
| `0x00084` | `SEC` | 写秒暂存值；读当前秒并同时快照纳秒 |
| `0x00085` | `NS` | 写纳秒暂存值；读上次 `SEC` 读取时的纳秒快照 |
| `0x00086` | `OFFSET_SEC` | RO，最近校正量的有符号 32 位秒部分 |
| `0x00087` | `OFFSET_NS` | RO，最近校正量的非负纳秒余数，小于 1000000000 |
| `0x00088` | `SYNC_COUNT` | RO，从端校时次数，32 位，复位清零 |

写时间先写 `SEC`、`NS`，再写 `CTRL`.load，`NS` 的配置范围为 0–999999999；应在没有 RTC 消息在途时设置模式和时间。偏差表示为 signed(`OFFSET_SEC`)×1000000000+`OFFSET_NS`，例如 −12 ns 编码为秒 −1、纳秒 999999988。

采用简单网络时间协议（Simple Network Time Protocol，SNTP）的 48 字节 v4 报文，格式依据 RFC 4330，多字节字段大端。

| 字节 | 从端请求 | 主端回应 |
|---|---|---|
| 0 | `0x23`：LI=0、VN=4、mode=3 | `0x24`：LI=0、VN=4、mode=4 |
| 1 | stratum=0 | stratum=1 |
| 2–3 | Poll=4、Precision=−26 | 同左 |
| 4–11 | Root Delay、Root Dispersion 为 0 | 同左 |
| 12–15 | 0 | Reference ID 为 LOCL |
| 16–23 | 0 | 最近配置装入时刻的 Reference Timestamp |
| 24–31 | Originate=0 | 原请求 Transmit 的逐位副本 |
| 32–39 | Receive=0 | 主端接收请求的 t2 |
| 40–47 | 从端发送请求的 t1 | 主端发送回应的 t3 |

t1、t3 在服务消息首字节与发送核心握手时采样，t2、t4 在接收核心交付首字节时采样。纳秒与 NTP 二进制小数由 `afdx_ntp_fraction` 换算，每次 32 轮、每轮两拍；编码为 floor(ns×2^32/1000000000)，解码取整纳秒并四舍五入。发送和接收/参考时间各有编码器，从端顺序解码 t2、t3。

从端仅在版本、模式和 Originate 与当前请求完整 Transmit 匹配时使用回应，计算 offset=((t2−t1)+(t3−t4))/2。秒与纳秒分拍运算、规范化，再把校正量加到应用时的当前时钟，补偿 32 ns 计算流水。回应等待超过 `PERIOD` 后用新时间戳重发，校时计算期间不发新请求；主端只回应。实际请求间隔由 `PERIOD` 控制，不用报文 Poll 字段控制调度。实现边界见第 9 节。

### 6.3 SNMP：配置和统计的网络访问

简单网络管理协议（Simple Network Management Protocol，SNMP）代理启用后认领 UDP 目的端口 161。回应源端口为 161，目的端口为请求源端口，使用配置的 `TX_VL`。支持 v1（version=0）和 v2c（version=1）的 Get、GetNext、Set，回应保留 request-id、community；主动通知使用 v2c Trap。

UDP 载荷采用抽象语法记法（Abstract Syntax Notation One，ASN.1）的基本编码规则（Basic Encoding Rules，BER），格式对照 RFC 1157、RFC 3416、RFC 3418。

| 报文层次或操作 | 编码内容 |
|---|---|
| 消息 | SEQUENCE：version INTEGER、community OCTET STRING、PDU |
| PDU | request-id、error-status、error-index、VarBindList |
| 单变量绑定 | OBJECT IDENTIFIER 与值 |
| PDU 类型 | Get=A0、GetNext=A1、Response=A2、Set=A3、v2-Trap=A7 |
| 长度形式 | 短形式、81 和 82 定长形式；不支持不定长 |

请求最长 256 字节，OID 内容最长 16 字节，community 长度 1–16，每请求一个变量绑定，管理端等待回应或超时后再发下一请求。请求和回应各用 256×8 RAM。Get 精确匹配；GetNext 按 OID 数字子标识比较，返回严格更大的首个对象。

查询不存在对象时，v1 返回 noSuchName(2)、error-index=1、NULL；v2c Get 返回 noSuchObject，GetNext 末尾返回 endOfMibView，error-status/index 为 0。错误 community 静默并计数，不支持操作不回应。

| 字地址 | 名称 | 读写与含义 |
|---|---|---|
| `0x00090` | `ENABLE` | RW，位 0，复位 0 |
| `0x00091` | `TX_VL` | RW，低 7 位，复位 0 |
| `0x00092` | `COMMUNITY_LENGTH` | RW，低 5 位，使用范围 1–16，复位 6 |
| `0x00093`–`0x00096` | `COMMUNITY_0`–3 | RW，每字高字节在前；复位 7075626C、69630000、0、0，即 public |
| `0x00097` | `SAMPLE_CYCLE` | RO，上一次 MIB 读取被授予时的 `now` |
| `0x00098` | `UPTIME` | RO，10 ms 单位，从复位持续累计 |
| `0x00099` | `REQUESTS` | RO，被认领请求在末字节时累计，含错误 community 和不支持操作 |
| `0x0009A` | `BAD_COMMUNITY` | RO，错误 community 次数 |
| `0x0009B` | `TRAP_ENABLE` | RW，位 0，复位 0 |
| `0x0009C` | `TRAPS_SENT` | RO，完整 Trap 提交发送核心的次数 |
| `0x000A0`–`0x000A3` | `DESCRIPTION_0`–3 | RO，16 字节 sysDescr，按高字节先读 |

管理信息库（Management Information Base，MIB）用配置寄存器作为数据源。主机优先，同地址主机读与 SNMP 读可合并，其他冲突时 SNMP 保持请求。SNMP 写仅在主机无读写且 `cfg_ready` 时授予，写后读回生成回应；内部读不产生主机 `cfg_rvalid`。`ENABLE`、community、`TX_VL` 应在管理消息不在途时设置。

### 6.5 615A：数据加载、卸载与文件格式

`afdx_615a` 是目标端，加载端经 UDP 和简单文件传输协议（Trivial File Transfer Protocol，TFTP）提交文件清单，目标读取头文件、数据文件，校验后存入加载 RAM。介质定义卸载把最近成功加载的 RAM 内容以 `MEMORY.BIN` 提供。操作期间用户消息仍通过同一服务仲裁和 VL 调度发送。

文件格式以 ARINC 615A-2002 Supplement 2 与 ARINC 665-1 为依据；版本和来源见事实清单。线上配置版本为 ASCII A4，可选 A3，接收请求列表接受 A3/A4。版本标记只表示文件编码选择，完整协议支持范围见第 9 节。目标标识为 `DEMC3_1`，多字节字段大端。

| 文件或载荷 | 当前格式与范围 |
|---|---|
| LUI、LND、LCI、LNO 初始化文件 | 长度、两字节版本、两字节状态、一字节描述长度及描述；正常/不支持且空描述时为 9 字节 |
| LUR 上传请求 | 总长、版本、头文件数、含 NUL 的头文件名和件号；仅一个头文件，字段长度 2–64，文件上限 512 字节 |
| LUH 加载头 | 665-1 版本 8002，头文件字数、绝对数据列表指针、数据文件数、文件名、件号、数据文件字数和 CRC-16；上限 2048 字节，仅一个数据文件 |
| 数据文件 | 正偶数字节，最多 8192 字节，文件名 1–63 字符 |
| LUS 上传状态 | 总长、版本、全局状态、描述、counter、exception timer、estimated time、三位 ASCII 总比例、头文件数；条目含头文件名、件号、逐文件比例、状态、描述 |
| LNR 卸载请求 | 总长、版本、文件数、含 NUL 的文件名、用户定义数据长度和数据；仅 `MEMORY.BIN`，用户定义数据忽略 |
| LNS 卸载状态 | 公共字段同 LUS；文件条目只有文件名、状态、描述，不含件号和逐文件比例 |

上传流程为：

1. 加载端 RRQ `DEMC3_1.LUI`，目标返回 DATA1 的初始化文件，状态 0001，等待 ACK1。
2. 目标 WRQ/DATA1 发送初始 LUS 0001，此时头文件数为 0。
3. 加载端 WRQ `DEMC3_1.LUR`，目标 ACK0、按块接收并 ACK；完整核对长度、版本和单文件清单后保存名称与件号。
4. 目标发送 LUS 0002，主动 RRQ 清单中的 LUH；头文件和 CRC 合法后再发 LUS 0002，RRQ 数据文件。
5. 按顺序写数据 RAM 并累计 CRC。首个满块写入后暂缓数据 ACK，先用独立传输端口发送数值进度状态，得到状态 ACK 后继续。
6. 长度、CRC 均正确才确认末块并发送 LUS 0003、比例 100，最终状态获得 ACK 后寄存器 `STATUS` 变为成功。失败发送 ERROR 和 LUS 1003，文件状态为 1007。

介质定义卸载先 RRQ `DEMC3_1.LND`，再接收 WRQ `DEMC3_1.LNR`；目标报告 LNS 0002 后主动 WRQ `MEMORY.BIN`，读取 RAM、逐块发送 DATA 并等待 ACK。首个满块确认后报告数值进度，最后短块或空块得到 ACK 后发送 LNS 0003，最终状态确认后成功。卸载不改变 `LOADED_BYTES`，上传和卸载不能并行。

每份新 LUS/LNS 的 16 位 counter 加一，重发不加；每次操作的状态序列从 1 起。进度按上传已写字节或卸载已确认字节计算，成功前最多 99%，比例为右对齐三位 ASCII。exception timer 为 0，进行中 estimated time 为 FFFF，其余为 0，失败描述为 FAIL `n`。

### 6.6 TFTP、加载区与配置

TFTP 支持 RRQ(1)、WRQ(2)、DATA(3)、ACK(4)、ERROR(5)，使用 octet 模式、512 字节块、从 1 开始的块号；WRQ 用 ACK0 建立。初始目的端口为 `REQUEST_PORT`，复位 59；后续两端使用传输标识符（Transfer Identifier，TID）。目标的新传输 TID 从 `0x8100` 递增，主文件与状态文件各保存端口和块号。

文件长度为 512 的整数倍时，还须传送零字节末块。超时重发已保存的请求、DATA 或 ACK；重复 DATA 只重复 ACK，不重复写 RAM。`RETRY_LIMIT` 是初次尝试之外的重传次数，每次新交换重新计算。ERROR 不重传，收到对端 ERROR 结束相应操作。

RRQ/WRQ 的 octet 结束后可携带选项名/值字符串，目标忽略选项，直接返回 DATA1 或 ACK0，不返回选项确认 OACK；blksize、port 等不改变块长或端口。TFTP 报文格式对照 RFC 1350，选项行为对照 RFC 2347。

LUH 的字数和绝对指针以 16 位字为单位，字符串填充到偶数字节。目标核对实际头长、版本、文件数量、头 CRC、完整数据长度和数据 CRC。CRC-16 多项式为 `0x1021`，初值 FFFF，最高位先算、无结果反转；头 CRC 覆盖除末尾 Header CRC 与 Load CRC 六字节之外的头文件，数据 CRC 覆盖整个数据文件。

| 字地址 | 名称 | 行为 |
|---|---|---|
| `0x000B0` | `ENABLE` | RW，位 0，复位 0 |
| `0x000B1` | `TX_VL` | RW，低 7 位，复位 0 |
| `0x000B2` | `STATUS` | RO，位 1:0 为 0 空闲、1 进行中、2 成功、3 失败；位 15:8 为原因 |
| `0x000B3` | `LOADED_BYTES` | RO，本次已写字节数，新上传清零 |
| `0x000B4` | `MEMORY_ADDRESS` | RW，低 13 位，读回加载区字节地址 |
| `0x000B5` | `MEMORY_DATA` | RO，低 8 位为 RAM 字节，B4 写后等至少 4 拍再读，仅非进行中有效 |
| `0x000B6` | `LUS_COUNTER` | RO，本次新 LUS/LNS 文件数，16 位回绕 |
| `0x000B7` | `RETRY_TOTAL` | RO，复位以来的超时重传次数，32 位回绕 |
| `0x000B8` | `REQUEST_PORT` | RW，低 16 位，复位 59，写 0 无效 |
| `0x000B9` | `TIMEOUT_CYCLES` | RW，复位 250000000 拍即 2 秒，写 0 无效 |
| `0x000BA` | `RETRY_LIMIT` | RW，低 8 位，复位 1，0 表示不重传 |
| `0x000BB` | `PROTOCOL_VERSION` | RW，低 16 位，复位 `0x4134`；仅接受 `0x4133` 或 `0x4134` |

`ENABLE`、`TX_VL`、`REQUEST_PORT`、`TIMEOUT_CYCLES`、`RETRY_LIMIT`、`PROTOCOL_VERSION` 在 `STATUS` 进行中时写入无效；`MEMORY_ADDRESS` 可设置，但数据只在非进行中读取。原因码为：0 无错误，1 元数据不支持/无效，2 容量或长度，3 CRC，4 对端 TFTP ERROR/模式错误，5 重传耗尽。

五块 RAM 分别为 RX 报文 1024×8、TX/重发报文 1024×8、LUR 512×8、LUH 2048×8、加载区 8192×8。新上传撤销上次有效长度，失败时 RAM 可能含部分或损坏数据，只有成功状态与有效字节数共同定义可用内容。加载区只存 RAM，不执行程序或写非易失存储。

忙时初始化请求返回 1000 和 BUSY；没有有效数据的 LND 返回 1000 和 NO DATA；未支持的 LCI/LNO 返回同名初始化文件、状态 1002，不启动后续操作。拒绝回应由单独的发送状态产生，保持正在进行的传输及重发内容。

## 7. 验证方法

### 7.1 测试平台、参考模型与独立核对

模块测试通过被测模块端口驱动、检查，系统测试用两个 `AFDX_top` 经 A、B 双网的四条单向链路互连。端点模型提交应用消息、写读公开配置口、采样交付和事件；链路模型支持固定周期延迟、丢帧、异或指定字节、扣帧重放和插入报文，检查线路动作是否满足帧间隔，避免用隐式排队改变设定延迟。

Python 参考模型按报文格式和协议规则生成输入及期望值，CRC 使用独立标准库。确定性场景在仿真内逐字节核对；调度先后依赖运行状态的场景记录消息、事件、GMII 帧和周期，由独立检查器在仿真后重建发送、链路动作、接收判定和交付。SNMP 用独立 BER 编解码，RTC 用整数时间向量，615A 用独立文件与 CRC 生成器。

系统记录使用共同周期计数：激励在下降沿准备，端口在上升沿非阻塞赋值更新前采样。GMII 帧记录包含网络、起始周期、字节数和十六进制内容；可转换为去除前导和 FCS 的 pcap，用 Wireshark 核对协议。性能窗口按记录周期裁取，每个方向分别计数，A/B 冗余副本不叠加。

测试须打印完整的 RESULT PASS 且错误数为 0；配有独立检查器时还须 CHECK PASS，工具退出码不能单独证明通过。RAM 仿真监视同地址同时读写，出现碰撞或仿真 Error/Fatal 即失败。波形和抓包来自真实仿真输出。

### 7.2 回归分类与评委入口

回归包含基础存储/MAC、发送分页与 BAG、接收错误/序号/冗余、双端用户通信与配置/复位、服务报文与失败恢复、容量/突发/性能等类别。各功能有正常和相关异常或边界场景；具体测试、参数、检查项目和结果见[补充数据的回归表](FACTS_DETAIL.md#逐项回归与评委入口)。

评委从仓库根目录的 ModelSim Transcript 运行 do sim/run_judge.do，覆盖五功能、配置容量、SNMP、突发、RTC 和性能。eLinx 工程的行为仿真入口为 tb_elinx，完整 RTL 回归入口为 sim/regress.ps1；软件准备、命令及预期输出见 [README](../README.md)。

性能核对区分稳定错开提交、同拍突发及服务竞争。端到端时延按应用末字节到对端交付末字节记录，线路固定延迟的扣除另行标注；同 VL 相邻发送间隔偏差、同长度消息时延极差与相对理想释放时刻的排队偏差分别统计，不能互相替代。

### 7.3 综合后功能仿真

界面综合与命令行综合使用各自产物和原厂单元模型。界面先运行 Run Synthesis，再用 `sim/run_gui_netlist.ps1` 仿真；脚本将 VQM 复制到独立输出目录，补齐未连接输入的默认值及实际连接进位端口的使用标记，保留既有连接、参数和 LUT 内容。命令行先综合 `sim/tests_netlist.txt` 列出的各顶层，再运行 `sim/regress.ps1 -Netlist`；仿真副本对 LUT 掩码文本作等值格式转换，并补齐模型所需默认值，不覆盖原网表。

模块网表用固定短激励，整顶层核对 GMII、应用交付、配置和事件记录；五功能网表使用 tb_net_services，同一激励还要与通过检查的 RTL 外部记录逐字节比较，并独立解码服务报文。脚本核对源文件和网表摘要，源码变化须重新生成对应网表。

综合网表功能仿真不含布局布线延迟。功能、时序和性能证据分别记录，覆盖范围与实测结果见事实清单；整顶层完整性能矩阵的网表验证属于第 9 节的未完成范围。

## 8. 资源和性能的设计值

### 8.1 存储规模与时序组织

默认表规格见第 3、4 节，服务存储见第 6 节。逐 VL 状态采用 RAM，浅的字节预取、页归还和交付队列采用小寄存器组。同步 RAM 的地址、使能和写数据寄存，读出后再寄存并参与算术；配置握手避开查表读，设计不依赖同地址同时读写的结果。

加减、时间比较和校验和按拍展开；地址用位拼接，宽选择分组并寄存。CRC 是组合字节更新，`ready`、`cfg_ok` 和服务通路选择为组合逻辑，数据存储与主要时序状态仍由寄存器控制。

逻辑表的深度×位宽用于计算存储预算，不能直接当物理块用量。eLinx 映射可把表拆成单比特切片，物理块还涉及打包；不同综合入口的资源统计口径必须分别说明。实际 LUT、触发器、RAM、引脚、建立/保持时间裕量和频率估算统一见[事实清单](FACTS.md)。

### 8.2 时间、缓存与线速设计值

| 项目 | 设计值 |
|---|---|
| 全设计时钟 | 单时钟，125 MHz，8 ns 约束 |
| GMII 帧内速率 | 每网每拍一字节，1 Gbit/s |
| 前导与帧间隔 | 前导 8 字节，帧间隔至少 12 拍 |
| 单帧占线加间隔 | 64–1518 字节帧对应 84–1538 拍，即 0.672–12.304 µs |
| 发送 VL 与页池 | 128 条配置，256 页×512 字节，128 KiB |
| 最长消息 | 1471 字节，3 页 |
| 接收 VL 与缓存 | 4096 条配置，每网 4 KiB 环，32 项交付描述 |
| BAG | 单位拍，1 ms=125000 拍；`LOOKAHEAD`=512 拍 |
| 冗余时间单位 | 4096 拍，即 32.768 µs |
| RTC 默认请求周期 | 125000 拍，UDP 端口 123 |
| SNMP 端口 | 请求/回应 161，通知目的 162 |
| 615A 默认设置 | 请求端口 59，超时 250000000 拍，额外重传 1 次，加载区 8192 字节 |

满长帧的理论载荷率可由 1471 字节载荷除以 1538 拍占线时间计算，实际吞吐还受 VL 释放、BAG、仲裁和测量窗口影响。零排队、突发及服务争用是不同工况，实测数字和适用条件均引用事实清单。

综合采用 8 ns 时钟约束，不以虚假路径例外或未给出的外部 I/O 延迟掩盖时序问题。综合时序估算、布局布线时序和实体测量分别说明，不能由功能通过推导物理时序通过。

## 9. 未实现的功能和已知限制

- **发送缓存容量。** 128 条发送 VL 是配置上限。页池共 256 页×512 字节，一条完整 1471 字节消息占 3 页，静态驻留按页计算最多 85 条，因此不能保证 128 条 VL 同时各排一条最长消息。首页或跨页申请无页时拒收整条消息，先归还已占页、消费到 `last`，最后给 `ev_drop_nopage` 并累计 `0x00044`；部分消息不入队，不无限等待。
- **调度与交付容量。** 跨 VL 轮询不保证全局消息入队顺序；提前候选可能使其他小帧等待，BAG 不等于任意争用下的精确发送周期。接收出口每拍一字节，两路独立非冗余满速输入可能填满环或描述队列，溢出时回退并计数。近同时到达时不承诺选择物理先到网；超过 `skew_max` 的后到副本可能再次交付。
- **AFDX/IP。** 未实现子 VL（Sub-VL）、IP 分片重组、ICMP 回显、采样端口及队列端口的完整语义。应用获得带 VL 索引和 UDP 端口的消息流；发送 UDP 校验和为 0，接收未按目的 IP 过滤。
- **SNMP。** 未实现 GetBulk、单请求多变量绑定和 v1 格式 Trap；未建立多个管理请求的排队能力。私有子树使用演示企业号，v2c 的 noSuchInstance 异常语义未完整覆盖。
- **615A 与加载头。** 未实现信息操作、操作员定义卸载的后续传输、FIND、WAIT、ABORT、整文件重试、多文件加载及后续版本的 TFTP 选项协商与语义。LUH 不匹配加载件号和硬件 ID，不处理支持文件、用户数据、扩展点、Load CRC-32、解压或解密；现有介质定义卸载和文件版本标记不能证明完整协议兼容。
- **异常边界。** SNTP 未检查服务器 Stratum 和全零时间戳；TFTP ERROR 未核对来源端口，截断请求缺少完整长度拒绝。正常传输和已覆盖异常通过，不能替代这些检查。
- **验证与物理边界。** 未完成整顶层完整性能矩阵的网表仿真，未做实体硬件、独立晶振或非对称链路对时测量，也未完成当前版本布局布线时序签核。布局布线导出的网表还有 RAM 位序与配套模型不一致的功能问题；具体证据见事实清单。综合后功能仿真只证明其已覆盖场景。

上述功能范围与[事实清单第七节](FACTS.md#七未实现及未验证的范围)、[README 的功能和限制说明](../README.md)对应。报告引用性能时，应同时引用其测量边界和未覆盖范围。
