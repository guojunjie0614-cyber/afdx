# Domain Docs

本项目采用 single-context 领域文档布局。

## 探索代码前

- 若根目录存在 `GLOSSARY.md`，先读取其中的领域术语。
- 若存在 `GLOSSARY-MAP.md`，按其指引读取相关上下文的术语表。
- 阅读 `docs/adr/` 中与当前工作相关的架构决策。
- 若后续采用多上下文布局，也检查相关
  `src/<context>/docs/adr/`。

上述文件不存在时，直接继续，不将其缺失视为问题，
也不提前建议创建。由 domain-modeling 在术语或决策
真正确定后按需建立。

## 默认布局

- `GLOSSARY.md`：项目统一术语表。
- `docs/adr/`：项目架构决策记录。

## 使用术语

任务标题、设计建议、排查假设及测试名称应沿用术语表定义，
避免使用术语表明确排除的同义词。

需要的术语尚未定义时，先检查是否误用了项目语言；
确有缺口时，记录为 domain-modeling 的后续输入。

## 决策冲突

若建议与现有 ADR 冲突，应明确指出对应 ADR、
冲突内容以及重新讨论的理由，不应静默覆盖已有决策。
