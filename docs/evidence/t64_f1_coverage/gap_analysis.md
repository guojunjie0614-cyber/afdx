# T64 未覆盖项分析

分析对象是冻结 `e5cd815020448820c2de7c587f288554defb74bc`、CE_DIV=2、默认种子 20261007 的 40 项回归。以下分类不改变任何工具分母、不增加排除项，也不把源码推理当作另一次仿真。完整索引为 [uncovered_index.csv](uncovered_index.csv)，逐模块数量对账为 [index_validation.json](index_validation.json)。每条索引给出当前源码行、原始报告行、未覆盖项及本文件中的分析组。翻转按连续位段压缩，每个方向每位仍各算一个 bin；条件和表达式按工具的输入项计数，不能用未命中的真值表行数替代。

## 分类口径

- **A：实际可达但本批未覆盖。**给出能够触发的输入、复位或事件条件；建议属于后续工作，本卡未执行。
- **B：在本批配置及明确假设下不可达。**限定 CE_DIV=2、现有参数集合、正常复位及无寄存器故障注入；给出常量或赋值集合依据，不推广到其他配置或故障模型。
- **C：工具识别、插桩或统计口径问题。**保留原始诊断与分母，不能理解为覆盖率豁免。
- **U：尚不能判断。**工具报告足以证明未覆盖，但尚不足以证明可达性或原因。

### R02：RTC 中止未覆盖全部计算及发包阶段，A

### A01：应用入口的拥塞、坏消息和回滚，A

### A02：A 网交付队列满错误计数，A

### A08：RAM 同拍同址读写诊断守卫，A

## 配置及服务协议

### A03：SNMP BER、OID 与 SET 数值错误，A

16 项。第 1090 行处理 OID 最后字节仍带 continuation 标志；第 1140–1142 行处理可写对象的数值长度小于 1 或大于 5；第 1181–1183 行处理负数或高 16 位非零。均由收到的请求内容直接控制，触发建议是最后 OID 字节置高位、合法 Gauge32 tag 配合错误长度，以及负数/大于 65535 的写值。应分别检查 v1/v2 的错误码、原 OID/值回显和配置未被误写。[源码](../../../rtl/afdx_snmp_engine.v#L1088)、[未覆盖报告](raw/afdx_snmp_engine_uncovered.txt)。其余解析错误项没有逐项证明可达性，仍在 U00。

### A04：加载/卸载协议异常，A

45 项，定位于第 1462–1590、1974–2216 行中索引明确列出的检查。主要缺口是状态文件确认耗尽重试、远端 TFTP ERROR、重复/非预期块号、错误目标文件名及模式、LUR/LNR 长度与字段、头文件版本/指针/CRC/文件数量/文件名、超限数据大小及最终长度不符。例如 [重复块处理](../../../rtl/afdx_615a_engine.v#L1548)应只重发 ACK，不重复写加载区；[头文件校验](../../../rtl/afdx_615a_engine.v#L2110)的失败语句尚未命中。建议优先做重复块、丢失状态 ACK、远端 ERROR 和错误 CRC，再做格式字段及长度边界，每次同时核对内存、返回状态、错误码和下一次事务恢复。B01 的四个常量分支单独处理，未混入此组。

### A05：RTC 纳秒与偏差的进位，A

11 项。第 458–464 行 `final_overflow` 触发秒进位及纳秒回卷，第 807–811 行正偏差溢出触发偏差归一化。建议把可配置时间或有效回应的计算结果放在十亿纳秒边界两侧，检查秒、纳秒及后续时钟连续性。本批常规同步成功不证明这些边界正确。[源码](../../../rtl/afdx_rtc.v#L458)。

### A07：RTC 非拆分配置读口的地址分支，A

18 项，主要在第 420–432 行。该段受 `SPLIT_CFG_ADDR!=2` 控制；顶层通常使用拆分读口，但当前测试还实例化了默认配置的 RTC，故不能把整个设计单元的这些零命中项都宣布配置不可达。建议在默认读口实例中读 VL、port、秒/纳秒快照、offset 与默认地址，检查读秒快照关联。[源码](../../../rtl/afdx_rtc.v#L409)。

## 常量和插桩口径

### B01：四类小报文的 candidate_read 恒零，B

8 项，为第 1764–1780 行的 4 个 true 分支和 4 个 `get_byte` 语句。`PK_ACK/PK_LUI/PK_ERROR/PK_LUS_WRQ` 的 `candidate_read` 仅在复位及有效 CE 拍赋零，全部赋值见第 703/709、724/730、748/754、769/775 行，没有赋一来源。因此在本批 CE_DIV=2、正常复位配置下这四条访存路径不可能触发。不能把此结论推广到将来改变候选生成逻辑的版本。

### B02：小型控制器的非法状态 default，B

8 项，为应用 TX 第 173 行、应用 RX 第 81 行、NTP 换算第 85 行、RX 引擎第 593 行的 default 分支和语句。正常复位后，其状态仅接受源码列出的常量；RX `op` 是两位寄存器，合法集合覆盖全部四个二态值。有限赋值集合在普通推进中闭合，所以本批合法复位、无强制赋值或状态故障注入时不能到达 default。四态 X、寄存器翻转、其他故障模型不在此结论范围。

### B04：状态寄存器的冗余高位，B

4 个翻转方向 bin。`afdx_rx_parse.length_phase` 第 116 行声明为三位，所有赋值只有 `LEN_WAIT/LEN_SIZES/LEN_LIMITS=0/1/2`；`afdx_tx_free.phase` 第 46 行声明为三位，所有赋值只有 `POP_IDLE/POP_READ/POP_CAPTURE/POP_REPLY=0/1/2/3`。正常复位后 bit 2 恒零。工具详细报告列出了这两个高位，但优化后的 DU dump 没有直接定位；索引以已核实的寄存器声明补齐，分母和 4 个缺口均保留。

### B05：配置读数据的显式补零位，B

842 个翻转方向 bin。[RTC 第 949–952 行](../../../rtl/afdx_rtc.v#L949)、[SNMP 第 471–482 行](../../../rtl/afdx_snmp.v#L471)、[加载包装第 560–570 行](../../../rtl/afdx_615a.v#L560)中，`{N'b0, value}` 的高 N 位由字面常量零驱动。只把索引范围完全落在补零段的位归为此类；一个原始报告位段跨过常量/变量边界时，索引按边界拆开，逐位方向数量保持不变。变量位不因同段补零而被豁免。本批 RTL 常量连接足以支持这一判断。

### C01：RAM 地址宽度函数在 elaboration 执行，C

7 项。[address_width](../../../rtl/afdx_ram_sdp.v#L10)仅由第 20 行 `localparam AW=address_width(DEPTH)` 调用，在 elaboration 求常量，不是运行时访存路径。原始报告第 14–16 行的语句/分支/条件计数全为零，与存储器读写是否执行不能等同；RTL 存储器运行语句已有命中。该静态函数仍在工具分母中保留。

### C02：CRC 组合循环控制变量的翻转，C

64 个方向 bin。[CRC 循环](../../../rtl/afdx_crc32_d8.v#L16)中的 `integer bit_index` 被报告为 32 位节点，全部方向计数为零；同一设计单元功能语句 6/6、分支 2/2。由源码和原始报告推断这是组合循环展开/优化后的记录口径；没有证明工具内部具体优化过程，不能把零翻转直接解释为 CRC 功能未执行。高位结构限制和低位 delta-cycle 记录未再细分，全部保留 C 分类及原始计数。

### C03：多参数设计单元的表达式标签，C

1 项。[TX free 原始报告](raw/afdx_tx_free_uncovered.txt)第 52 行表达式标题显示 `(count < 32)`，输入项表却显示 `(count < 256)`。源码使用 `count < PAGES`，测试参数集合同时包含 32 页和 256 页实例。这是按源码设计单元合并时的标签口径限制，不把其中一个参数标签当成所有实例的可达性证明，也不修改统计结果。原始报告及参数化用例均保留。

## 翻转长窗口及其余未知项

### A06：时间基准的高位，A

### A09：事件计数器高位，A

## 后续补测优先级

1. **P1：运行中恢复与数据完整性。**R01/R02 逐状态复位/中止；A02 A 网队列满及回收；A01 应用缓存/描述符边界。重点观察有无旧数据外发、丢失归还、重复交付和下一事务无法恢复。
2. **P1：加载协议可靠性。**A04 重复数据块、丢状态确认、远端 ERROR、坏 CRC/长度及事务重启，优先于单纯增加随机包数。
3. **P2：服务字段及时间边界。**A03 畸形 BER/OID/SET，A05 RTC 进位与正偏差，A07 非拆分读口；F03 重复匹配回应。
4. **P2：关联可达性证明。**先补主状态/辅助状态合法组合表，解决 F01/F02/F04；补测可达弧，不为工具候选弧盲目构造非法路径。
5. **P3：计数器进位及工具口径。**A06/A09 用独立边界验证；C01/C02/C03 保留原始诊断后再决定是否另卡研究工具设置。本卡没有增加测试、故障注入、RTL 修改或排除项。
