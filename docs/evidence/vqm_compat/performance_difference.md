# 旧性能检查器与公开应用口口径差异说明

本文说明早期定拍注入检查器（`tb_sys_perf`，种子 `20261007`，`CE_DIV = 2`）下出现 `702` 项差异的原因。后续按公开应用端口实际发送起止节拍复算，分片交付版已通过评委验收，当前结果见 [sim/reference/judge_result_frag1030.txt](../../../sim/reference/judge_result_frag1030.txt) 的 `JUDGE CASE PASS performance` 及 [frag_load 实测摘要](../frag_load/performance_actual_check_summary.json)。

## 差异数据拆解

- **RTL 内部自检与独立检查**：HDL 自检 `PASS checks = 683,408,635 errors = 0`，四份 TX/RX 独立检查与 GMII 检查均 `0` 错误；仅旧性能子检查器按“严格零残差”门槛计出 `702` 项超差（共 `1,325,290` 项外部检查）。
- **702 项差异构成**：
  1. `692` 项把内部 M 模块完成节拍直接当作固定应用注入拍比较（引入新增应用层分片流水线后两者不再重合）；
  2. `10` 项来自线上相邻同 VL 帧间隔偶发 `+1` 拍正偏移（`+8 ns`），未低于配置的最小 BAG。
- **实测间隔统计**：在公开应用输入 A 口统计的 `7,832` 个相邻同 VL 间隔均精确为 `125,000` 拍（内部 M 模块完成间隔为 `125,001` 拍 `5,215` 次、`124,998` 拍 `2,617` 次）；对应单网 GMII 线上的 `7,832` 个相邻同 VL 间隔中，`7,488` 次为 `125,000` 拍、`344` 次为 `125,001` 拍，无任何小于配置 BAG 的违例间隔，最大正残差仅 `1` 拍（`8 ns`），77 VL 下行交付速率约 `906.136 Mbps`。

## 可复核时戳样本与复现方式

- **代表样本**：工况 `throughput_d0`、VLID `100`，相邻帧前导首字节节拍分别为 `12,475,356` 与 `12,600,357`，实测间隔 `125,001` 拍（相对 `125,000` 拍基准仅 `+1` 拍正偏移），未违反最小 BAG 约束。
